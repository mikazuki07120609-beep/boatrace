# 水面ノート

全国のボートレースの出走表を毎日自動で更新し、選手のコース別成績とレース場の特徴から「展開の見立て」と解説文を作るサイトです。買い目は出しません。

公開ページ: https://suimennote.com/(これまでの https://mikazuki07120609-beep.github.io/boatrace/ からは自動で転送されます)

## しくみ

1. GitHub Actions(`.github/workflows/update.yml`)が毎日 0:20・7:10・17:10(日本時間)に動きます。
2. 公式が配布している番組表・競走成績のファイルをダウンロードして読み取り、`data/program/`・`data/results/` に保存します(`scripts/update.py`)。
   - 過去の成績は、公式サーバーに負担をかけないよう1回10日分ずつ、直近1年分まで取り込みます。10日より前の成績は、集計に使う項目だけに縮めて保存します。
3. 成績から選手のコース別成績と戦法の傾向(直近1年: 勝ったときの決まり手、1コースで負けたときの決まり手)と、レース場のコース別成績(直近1年)を集計し(`scripts/stats.py`)、ページを作ります(`scripts/build_site.py`)。
4. 見立てモデルを学習し直します(`scripts/fit.py`)。過去の各日について「その日の朝に分かっていたデータ」だけで見立てを作り直して実際の結果と比べ、直近の日(学習に使わない日)の成績を `data/eval.json` に、全期間で学習し直した重みを `data/model.json` に保存します。
5. できたページを GitHub Pages で公開します。締切前のレースの見立ては `data/pred/` に記録し(`scripts/predlog.js`)、結果が出たら各レースのページと「答え合わせ」のページで比べます。

見立ては2段階です(`site/assets/model.js`。式は `scripts/fit.py` と同じ)。

- スタートの見立て: 選手の平均ST(走数で全体の平均に寄せる)・コース・フライング持ち(F1/F2)・風速・直近8走の調子・両隣の選手のスタートの傾向・場の補正から予想STを出し、過去のレースで実際に起きたスタートのずれ方(全員そろって遅れる、スロー勢とダッシュ勢でずれる、たまに大きく出遅れる艇がいる)を当てはめて、400通りのスタートを作ります。各艇の「出る(両隣より0.05秒以上早い)」「凹む(0.05秒以上遅い)」確率もここから出します。
- 展開の見立て: STの組み合わせごとに、どのコースがどの決まり手で1着になりやすいかを条件付きロジットで計算し、400通りで平均します。

各レースのページの「スタート」のタブ(`site/assets/race.js` の `renderStart` から)は、スタートの見立てをまとめて見る場所です。展示の前は枠なりの進入・ふだんのSTの目安で出し、スタート展示のあとに計算し直します。

- スタートの見立て: 予想ST・一撃スタート(両隣より0.05秒以上早い)・凹む(0.05秒以上遅い)の見込みと、選手ごとの材料。頭に、スタートが分かると見立てがどれだけ当たるようになるか(`data/eval.json`)を出します。
- スリットの隊形: 予想STと、10回に4回はこの間に入る幅の図(終わったレースは実際のSTも)。
- 一撃スタートと出遅れの根拠: 艇ごとに、見込みを上げる材料と下げる材料(両隣との差・ばらつき・展示ST・コースのくせ・最近のST・フライング持ち・前づけ)。
- スリットから1マークまで: 400通りのスリットを形(1コースが凹む・カドが一撃など)で分け、そのときの1コースの逃げと、逃げ以外で一番多い決着を数えます。展開の見立ての各行にも、その決着になりやすいスリットの形を添えます。

各レースのページには「1周1マーク展開ビュー」(`site/assets/turn1.js`)があります。展開の見立てで上位の決着パターンを、そのパターンになりやすいスタートの並び(スタートの見立てから計算)で動かし、スタートして全艇が1周1マークを回り切るまでを上空から見たシミュレーションとして描きます。

- 戦法の動き: 差しは内の艇を先に回らせてその内(ブイ際)を小回りで、捲りは内の艇の前へ絞ってから外を全速で、まくり差しは隣の艇の前を横切ってさらに内の艇の内へ。捲られた艇は引き波で沈みやすく、そのぶん外の艇の差し・まくり差しが届きやすくなります。
- 動かし方: 戦法から各艇のライン(走る道筋)を決め、優先する艇(前を横切る艇・先に回る艇)から順に時間を決めます。後から決める艇は、ぶつからないよう譲りますが、譲るのはぶつかる直前の短い区間だけで、ターンの手前の減速もブイの近くで一気に落とします(レースなので、早めに速度を落として譲り合う動きにはしません)。
- スタート: 全艇がスタートラインを越えたところで、スリットの形(「4コースが内より0.04秒早い」など)を出します。
- 吹き出しの戦法名は、走らせた結果の位置関係(どちら側を通って前に出たか・前を横切ったか)から決めます。
- 結果が出たレースは、実際のSTと進入で動かした映像も見られます。動画として保存・共有もできます。

## 裏水面ノート(荒れ予報)

サイトの最初のページ(`index.html`)で、表の水面ノート(`today.html` から。当てにいく本線)と、裏水面ノート(`ura/` の下。荒れを狙う裏本線)を選びます。どちらも「今日のレース・レース検索・見立ての成績・このサイトについて」に分かれ、レースのページは同じタブの並びです(裏は色を反対の夜の配色に)。

- 払戻金: 公式の競走成績ファイルから、レースごとの払戻金(3連単・単勝など)を読み取り、`data/pays/YYYYMMDD.json` に置きます(`scripts/parse.py`・`scripts/pays.py`)。過去分は Actions の「払戻金の取り込み(過去分)」(`pays.yml`)で取り込みます。
- 学習(毎晩、`scripts/ura_fit.py` → `data/ura.json`): 過去のレースの見立てから3連単120通りの起こりやすさを出し、実際の配当と比べて「この組み合わせは100倍以上で売れそうか」の目安と、万舟(3連単1万円以上)の見込みの補正(風・波・場・レースの種類・前づけ)を学びます。場・風・波・風向き・時間帯ごとの万舟率と、最近の万舟も数えます。
- ページ(`site/assets/ura.js`・`site/assets/ura_page.js`): 見立て(表と同じ `model.js`)から万舟の見込みを出し、表の本線の艇以外で「その決着になって、しかも万舟になる」見込みが一番高い決着を裏本線にします。オッズが出たあと(締切の15分前から)は実際のオッズで計算し直し、人気と見立てのずれも出します。
- 答え合わせ: 締切前の裏の見立てを `pred.json` の `u` に記録し(`scripts/predlog.js`)、翌日に払戻金と締切時オッズで比べて `data/learn/YYYYMMDD.json` の `ura` に残します(`scripts/learn.py`)。

### 裏の追加の材料と知らせ

- 締切前の売れ方: オッズの取り込み(`scripts/odds.py`)が、そのレースで最初に取り込んだオッズ(締切の約15分前)を `first` として残し、オッズのタブと裏の「人気と見立てのずれ」に変化を出します。
- 潮の満ち引き: 気象庁の潮位表(推算潮位)を `data/tide` に取り込み(`scripts/tide.py`。毎日の更新が今年の分を確かめる)、締切の時刻の潮をレースのページに出します。過去のレースの締切時刻は `data/times`(`scripts/times.py`)。過去分は Actions の「過去分の取り込み」(`past.yml`)で取り込みます。
- 穴をあける選手: 裏の学習が `data/ura_racers.json` に選手ごとの万舟絡みの数を残します。
- オッズを入れた万舟の見込み: 裏の学習が、締切時オッズ(odds ブランチの `data/odds_final`)のあるレースで、見立ての見込みと票の割合の合わせ方を学びます(`data/ura.json` の `mix`)。
- 直前の荒れ・知らせ: 展示のあとの裏の見込みを `data/live/YYYYMMDD/ura.json` にまとめ(`scripts/predlog.js`)、Cloudflare に置きます。大荒れ注意になったレースは RSS(`ura/feed.xml`)にも足します。
- X への自動投稿(使うときだけ): リポジトリの秘密の値に `X_API_KEY`・`X_API_SECRET`・`X_ACCESS_TOKEN`・`X_ACCESS_SECRET` を入れると、大荒れ注意になったレースを投稿します(`scripts/xpost.py`)。1日の上限はリポジトリの変数 `X_DAILY_MAX`(ふだん 3)。X API は1件ごとの料金です。
- Google Search Console: HTML タグで確かめるときは、タグの `content` の値をリポジトリの変数 `GOOGLE_SITE_VERIFICATION` に入れると、最初のページに入ります(DNS で確かめるときは要りません)。
- シェア用の画像: `site/assets/og-*.png`(`python3 scripts/make_og.py site/assets` で作り直す。Pillow と Noto Sans CJK が要る)。

## 開催中のデータの置き場所(Cloudflare R2)

締切の前後に取り込む直前情報・結果(`scripts/live.py`)とオッズ(`scripts/odds.py`)は、リポジトリ(GitHub)に入れるのと同時に、Cloudflare R2 にも置きます(`scripts/r2.py`)。ページは先に R2 を読み、ない・読めないときだけ GitHub(raw.githubusercontent.com)を読みます。GitHub のファイル置き場はサイトの配信用ではなく、ログインしていない人のアクセスに回数制限があるためです。

- R2 のキー: `live/YYYYMMDD/{場コード}.json`・`live/YYYYMMDD/dl.json`・`odds/YYYYMMDD/{場コード}/{レース番号2けた}.json`(バケット名 `suimen-data`)
- リポジトリの秘密の値(Settings → Secrets and variables → Actions): `R2_ACCOUNT_ID`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`。ないときは GitHub にだけ入れます。
- ページが読む公開のURLは `scripts/build_site.py` の `DATA_BASE`(いまは https://data.suimennote.com/。空なら GitHub だけを読む)。サイトのURLは同じファイルの `BASE_URL`。
- 設定がすんだら、Actions の「Cloudflare の置き場所の確認」(`r2check.yml`)を手で動かして確かめます。

## 手元で動かす

```
python3 scripts/update.py            # 公式ファイルをダウンロードして作る(lha が必要)
python3 scripts/update.py --offline  # data/raw にあるテキストだけで作る
```

できあがったサイトは `_site/` に出力されます。

## 注意

- 非公式のサイトです。データの読み取りに誤りが含まれる可能性があります。正確な情報は主催者発表のものをご確認ください。
- 展開の見立ては過去の成績をもとにした目安で、舟券の購入をすすめるものではありません。舟券の購入は20歳以上に限られます。
- レース場データの初期値(`data/stadiums.json`)は BOAT RACE オフィシャルウェブサイト「ボートレース場データ」より。成績が十分たまると、当サイトの集計に切り替わります。
